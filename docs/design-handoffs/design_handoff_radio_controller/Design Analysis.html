P0 — bugs and confusing readouts

Things that mislead the user every time the device boots.

Each of these has been observed on hardware. They aren't visual nitpicks — they are functional defects that make the radio source look broken or untrustworthy.

01
Signal meter can read 118 %
P0
Observed

On 92.30 MHz FM with a strong local signal the meter reads 118 % while the 20-segment bar is fully lit. A moment earlier it read 111 %. Percentages above 100 % shouldn't exist; the bar can't fill any further so the number contradicts the visual.

Why it happens

The value bound to SignalStrength is a raw RTL-SDR power reading that's not normalised to a calibrated full-scale, and the segment colouring inside RadioControlPanel.razor (i < 12 ? green : i < 17 ? amber : red) assumes a 0–100 input domain that the data doesn't promise.

Proposed direction
  • Switch the readout to a calibrated dBu scale (–60 → 0 dBu) and label it RSSI, not "Signal %".
  • Drop scale labels under the bar (−60 −30 −12 0 dBu) so the user can anchor what each segment means.
  • Lift "overdriven front-end" to its own CLIP pill next to the value — don't encode it as "more than 100 %". CLIP only lights when the input is actually saturating; otherwise the bar is a clean 0–100 fill.

See canvas: P0 / Signal meter — 118 % is impossible.

02
AGC strip is half-empty whenever AGC is on
P0
Observed

The strip below the scan buttons has two cells: the AGC toggle on the left, and a slot on the right that holds a manual GAIN slider. When AGC is on, the slider is hidden — the right cell becomes a blank rectangle. The strip changes height between states.

Why it matters

Two real problems. First, the user can't see what gain the tuner has chosen — turning AGC off is a leap into the dark. Second, the empty cell makes the panel look unfinished; it reads as a layout bug, not a deliberate state.

Proposed direction
  • Treat the strip as two fixed cells that are always full.
  • The AGC cell carries the toggle plus an AUTO / OFF pill — the state is part of the label, not just the switch position.
  • The right cell shows the currently active gain in both states: when AGC is on, "Tuner is choosing — 28.0 dB"; when off, the slider and its range.

See canvas: P0 / AGC / gain strip — never half-empty.

03
"80 %" appears in every confidence cell
P0
Observed

The song-recognition panel (the table that replaces the album art when "Searching" is the current state) has a Conf% column. Every populated row reads 80 %. The two failed rows read --. The column is carrying no information.

Why it happens

The confidence value coming back from the fingerprinter is a coarse bucket (the library returns one of a few discrete grades), and the display is treating it as a free-form number. "80 %" is the threshold above which a match qualifies — not a per-track score.

Proposed direction
  • Replace the numeric column with a three-pip indicator + word label (Strong / Likely / Possible / No match). The pip count encodes the bucket; the word resolves it.
  • Drop the Art column (just a ✓ / ✗) and use the cover-art square as the row leader — present art renders, absent art gets a ♪ placeholder.
  • Lift the currently-playing row out of the table as a NOW anchor, with the rest of history dimmed below under an EARLIER heading. This is the actual question the user is asking when they look at the panel.
  • Remove the Fingerprints: 4.1/min · Lookups: 4.1/min telemetry from the header — it belongs in the dev tray, not the user-facing panel.

See canvas: P0 / Song recognition — kill the 80 % column.

P1 — structural improvements

The product feels twice as finished after these.
04
Tuner header & RDS info under-promoted
P1
Observed

The label TUNER sits at 9 px in the top-left corner with 0.45 opacity. The RDS station name and program type collapse to one tiny line under the frequency display: Don · CLASSIC ROCK. The user has to know the panel is broadcasting RDS data to even notice it.

Proposed direction
  • Promote TUNER to a real section header at the top of the centre column, with a band/range sub-header on the right (FM · 76–108 MHz).
  • Make band buttons tall pills with the band sub-range underneath (AM 535–1700 kHz, FM 76–108 MHz, etc.). Existing 32 px buttons are too small for the kiosk touch surface anyway.
  • Lift RDS to a card above the frequency display — station name in the cyan accent, program type in a chip. Add an RT line below the display that shows the rolling RadioText where supported.

See canvas: P1 / Tuner header & RDS.

05
Memory presets duplicate the frequency in the name
P1
Observed

Each preset reads WB - 162.55 MHz on the first line and 162.55 MHz · WB on the second. The slot number is rendered as a 9 px corner ghost at 20 % opacity. The "save" dialog seeds the name with the frequency, so users never override it.

Proposed direction
  • Restructure each row into three columns: slot number (left, mono, always visible), name (middle, body, can be the RDS station call sign), frequency (right, in DSEG amber).
  • When saving from the tuner, seed the name with the RDS station name if available, never the frequency.
  • Show empty slots in the bank as dashed placeholders — the user can see how much capacity remains and tap to save into a chosen slot.
  • Show "7 of 16" in the header so capacity is one glance away.

See canvas: P1 / Memory presets.

06
Source / gain / search status are three pills
P1
Observed

On the Radio Main Page the now-playing column has three pills: green ● Searching top-left, purple SDR RADIO (RTL-SDR) mid-top, and cyan 0dB top-right. They are colour-coded but visually unrelated — three floating tags doing related work in three different corners.

Worse, nothing on the album art tells the user whether the song name shown (Dirty Laundry · Don Henley · I Can't Stand Still) was matched by the fingerprinter or supplied as RDS metadata. The confidence the panel does compute never reaches the song display.

Proposed direction
  • Consolidate the three pills into a single status strip across the top of the now-playing column: source · frequency · RDS station · gain. Each cell keeps its semantic colour but the relationship is now structural.
  • Attach the match confidence to the song title where the user reads it — three pips + a word ("Strong match · 12 s ago"). This is the same indicator used in the recognition panel; consistency.

See canvas: P1 / Now Playing status.

P2 — polish

Smaller surfaces that punch above their pixel count.
07
Gain popover has no feedback meter
P2
Observed

Tapping the small 0dB pill on the now-playing column opens a 300 px popover with a single slider labelled SDR Radio (RTL-SDR) Level. Range runs from −∞ to +6 dB. There is no signal feedback while the user is dragging — adjusting the gain requires waiting for the next track to play to know whether the change improved anything.

Proposed direction
  • Add a live vertical peak meter beside the slider in the popover. User drags, watches the peak reach into the green / amber / red zone, releases.
  • Show an AUTO pill in the popover header that mirrors the tuner AGC state. When AUTO is on, the slider dims rather than disappearing — the user can see what the tuner has chosen.
  • Trim the title to SDR · RTL-SDR / RF gain; the existing string is the internal source ID.
  • Add a Reset to 0 dB button in the popover footer so the user has a one-tap escape.

See canvas: P2 / Gain control popover.

What's NOT in this pass

Out of scope, on purpose.
  • The album-art column itself — the proportions, the gradient backdrop, the typography inside. These read well as-is.
  • The scan controls (◀ SCAN / SCAN ▶ buttons). The current bezelled hardware buttons are good — the only change in the canvas is that they pair with the new AGC strip underneath them.
  • The visualizer column on the right (VU / Wave / Spectrum). Already handled in the first handoff pass — see design_handoff_radio_console/IMPLEMENTATION.md § P1·3.
  • The top bar source pills and route toggle. Same — see § P0·1 of the prior pass.
