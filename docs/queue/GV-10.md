## Detail

❌ **FALSIFIED 2026-09-06 as a Radio Console defect. Everything below this block is the superseded filing, kept because the reasoning is the asset and a deleted row gets re-proposed — but do NOT act on it without reading [`F-5-DIAGNOSIS.md`](../uat/2026-07-31-gv-live-data/F-5-DIAGNOSIS.md) first.**

**What the investigation found** (read-only pass over both repos, ~90% confidence on the falsification):

- **Two distinct fields, never cross-wired.** Conversation bubbles bind `SmsMessageDto.Text` (`MessageBubble.razor:10` → `DisplayText` at `:49-50`); thread-list rows bind `SmsThreadDto.LastMessagePreview` (`PhoneTextsPanel.razor:170` → `PreviewText` at `:248-249`). No code path feeds a preview into a bubble — `grep "new SmsMessageDto"` returns **zero** production hits.
- **No data truncation.** Every hop from Google's JSON to `@DisplayText` is verbatim, in both repos.
- **No CSS truncation on the bubble.** `.msg-bubble` has no `text-overflow`, no `-webkit-line-clamp`, no `max-height`, no `nowrap`; `.msg-text` has no rule at all. (The **thread-list row** does truncate visually, and renders U+2026 — display-only, and it touches the list alone.)
- **The original inference was invalid by construction.** F-5 reasoned *"the bubble matched the truncated list preview, therefore the view renders the snippet."* Upstream derives `LastMessagePreview` from **`SmsTextIdx` on the last message node** — the same wire slot `ParseSmsMessages` reads for the bubble's `Text`. The newest bubble and the preview are the same string **by construction** and would match even if both carried complete bodies. The observed match was guaranteed by the data path, not evidence about truncation.

**The residual is upstream-only and is a RotaryPhone concern:** is the wire value at `SmsTextIdx` a full body or a snippet? Source cannot answer it. If it is a snippet, that is a RotaryPhone item; `GV-10` closes here either way.

⛔ **Status deliberately left 📋, NOT ✅ — nothing shipped.** The row is falsified, not delivered. **Whether it closes outright or converts to a cross-repo note is the owner's call**, and the one command that decides it is in the diagnosis (`curl` a known-long non-group thread, inside a healthy auth window).

**Two consequences already recorded elsewhere:** `PHN-3` is **not** gated by this row — it reads `SmsMessageDto.Text`, the same field the bubble renders verbatim — and the plan's ⛔ *"do not strip a trailing ellipsis"* is right and needs no amendment. The diagnosis also exposed a coverage gap worth closing when `PHN-3` is built: nothing pins what a bubble renders for a non-null `Text`.
