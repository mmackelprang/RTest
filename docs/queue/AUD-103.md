# `AUD-103` — Band map for AM and SW: sweep plans, the HF mode in both sweep paths, and an UnavailableReason that reads the device

[← Builder Queue index](../BUILDER_QUEUE.md)

🟢 **P2, fourth all-band row.** Filed 2026-10-11 by the Planner. Read from code on `main` `2a2893d2`.

## Goal

The BAND view, Discover and map-driven Scan (`AUD-91`, `AUD-100`) should work on AM and SW the way they already
work on FM, WB, AIR and VHF.

## Measured facts

- **No AM or SW plan.** `BandSweepPlans.For` (`src/RTLSDRCore/Sweep/BandSweepPlans.cs:112-127`) handles FM, WB,
  AIR and VHF only. The class remarks say so (`:24`).
- **`UnavailableReason` uses static constants, not the device.** `:134-165` compare the preset range with
  `RtlSdrDevice.TunerMinFrequencyHz/TunerMaxFrequencyHz`. Its callers: `BandMapService.cs:271,340,1076`
  (`GetScanStations`, the request path, `MappableBands`) and `BandMapController.cs:83,136`. The Web shows it at
  `VisualizerPanel.razor:159-161`.
- ⚠ **Correction to the 2026-10-11 survey ("`ChannelPowerMeter` window is FM-sized"): only the parameter
  defaults are.** `ChannelPowerMeter`'s defaults are 80 kHz / 8 kHz (`ChannelPowerMeter.cs:62-63`), but
  `BandSweeper` always passes the plan's own window (`BandSweeper.cs:155,162`). `AUD-91` already gives
  narrowband plans **±4 kHz with 1 kHz DC exclusion** (`BandSweepPlans.cs:36-39`), and `CreateNarrowband`
  (`:180-206`) puts every channel at least half a spacing from the tuned centre. **A 10 kHz AM grid fits that
  as it is**: `NarrowbandGroupSize(10_000)` = 20 channels per tune, so 119 channels (530–1710 kHz) take 6 tunes.
  At 5 kHz SW it is 38 per tune. No new window type is needed unless the box shows otherwise.
- **Two sweep paths**, and both must be in HF mode for AM/SW: the idle path `DeviceSweepTuner`
  (`src/RTLSDRCore/Sweep/DeviceSweepTuner.cs:44-63`, opened by `BandMapService.RunIdle` `:748`) and the live path
  `RadioReceiver.RunLiveSweep` / `LiveSweepTuner` (`RadioReceiver.cs:1166-1240`, `:1326-1342`). `AUD-99` adds
  the switch itself. This row makes sure the sweeps ask for it and adds tests at the sweep level.
- **Sweep gain.** Both paths force manual tuner gain (`DeviceSweepTuner.cs:58-59`, `RadioReceiver.cs:1204-1205`;
  `BandMapOptions.SweepGainDb`). In direct-sampling mode the tuner is in standby and tuner gain means nothing.
  The sweep must not log an error per tune for it (see `AUD-99`), and AM levels will sit on a different absolute
  scale from FM's. Check the `UI-22` signal-colour thresholds (12/20 dB above floor) against real AM maps before
  trusting the colours.

## Scope

1. **AM plan:** 530–1700 kHz (or to the AM top edge `AUD-102` settles) at 10 kHz, through `CreateNarrowband`.
2. **SW plan.** The whole of 1.7–30 MHz at 5 kHz is about 5,700 channels. That is too many to sweep and to show.
   Recommended: follow the VHF precedent (`CreateVhf`, `:250-265`, a window that follows the radio). The SW plan
   is the **broadcast segment** containing (or nearest to) the radio's frequency, from a fixed table: 120/90/75/
   60/49/41/31/25/22/19/16/15/13/11 m, with ITU edges recorded in code. The plan states the table's source.
   ⚠ How the BAND view's axis presents a segment, and how Discover picks one when the radio is not on SW, are
   presentation questions. If the plan cannot answer them from `UI-31`'s existing strip and axis, ask the
   Designer briefly rather than inventing it.
3. **`UnavailableReason` reads the device.** Use the same capability `AUD-102` puts on `RadioBandModel` (one shared
   function, not a copy). The text for a device without HF should still read like today's sentence.
   `MappableBands` and the controller follow it. Keep the custom-band case.
4. **Sweeps in HF mode.** Both paths set HF mode per the plan's band before the first tune, and the idle sweep
   restores nothing (it closes the device). The live path only sweeps a band in the radio's current mode, or
   refuses with a reason (`AUD-99` § Scope 2 decides the mechanism).
5. **Map-driven Scan (`AUD-100`) on AM/SW.** `GetScanStations` (`BandMapService.cs:262-…`) works once the plan
   exists. Check the 10 kHz/5 kHz spacing assumptions in `BandMapStations.Peaks` and the seek-stop merge.
