68 ms is the first block after the start, so the detector reports a pilot whatever is on the channel. That
includes a channel believed empty. Re-measured on `aa502f6` with `AUD-106`'s lock indicator. The empty channels' pilot *level* is
0.11–0.15, higher than the real station's 0.065. Their in-phase component is 0.003–0.011, against 0.042–0.050 on
97.745 MHz. So the energy is noise, not a pilot. **Not established:** whether 87.5 and 107.9 MHz are really empty at the box.
Nobody listened, and the box master is muted.

## Read from code

`StereoFmDecoder.StereoDetected` is `_pilotStrength > 0.01`. `_pilotStrength` is the smoothed absolute value of
the 19 kHz band-pass output (18.5–19.5 kHz, 127 taps). It is not a lock indicator: noise in that 1 kHz band
already averages above 0.01, so the matrix decode (and `isStereo` in `/api/radio/state`) is on for noise. Nothing
checks the PLL's lock (for example `PllFrequency` staying near 19 kHz, or a phase-error measure).

## Why it matters

- The panel and the API report **STEREO on empty channels** and on weak mono stations, and apply the L−R matrix
  to noise.
- `AUD-106`'s watchdog keys on "no pilot and no RDS", so a fault whose composite is noise would read as
  "pilot" and not trigger. The one observed fault read `isStereo:false`, so it would have triggered.

## Scope (for the Planner)

A pilot detector that measures lock instead of band energy. `AUD-106` added `StereoFmDecoder.PilotInPhase` and
`RadioReceiver.IsPilotLocked` for its own use, and they separate the two cleanly on the box. Base the detector on those,
with a threshold tested on synthetic noise, a mono station and a stereo station through `RadioReceiver`.
`AUD-106`'s watchdog then uses the same verdict.
