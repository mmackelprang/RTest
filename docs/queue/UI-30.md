# `UI-30` — a disconnected visualizer says so in the visualization area; the header dot is removed

[← Builder Queue index](../BUILDER_QUEUE.md)

🚧 **BUILT 2026-10-02, HELD for owner panel UAT** — branch `fix/ui-28-29-shuffle-band-tab`, one PR with
`UI-28` and `UI-29`. Not deployed.

🟡 **P2 (owner ruling).** Filed 2026-10-02 by the Builder, from the owner's answer to `UI-29`'s green-dot
question.

> *"When the visualizer is disconnected, there should be an indication in the visualization space - not a
> small dot. Something like a disconnected icon in the main viewable area."*

## What changed

- **The dot is gone.** `.visualizer-conn-dot` (an always-visible 8 px green/red dot at the top-right of the
  picker header, from `PR 4`) is removed from the markup and the stylesheet. Nothing shows while connected.
- **While the visualization hub is not connected**, the canvas area shows, centred: a `link_off` icon
  (Radzen material icon, `--signal-amber`), **"Visualizer disconnected"** (mono uppercase, the type of BAND's
  "No scan yet"), and **"Reconnecting…"**. Amber rather than red because the hub reconnects by itself — the
  retry policy never gives up and nothing in the UI stops the hub — so this is a wait, not a fault to act on.
- **Precedence:** skeleton (canvas not initialised) → BAND's own states → **disconnected** → "Waiting for
  audio data". Without it, "Waiting for audio data" would wait for something that cannot arrive.
- **Accessibility:** `role="status"`, `aria-live="polite"`; the element is rendered once per disconnection,
  so it is announced on the change, not per frame.
- **Stale frame:** on a connected → disconnected change the canvas is cleared, so the last frame does not sit
  under the state looking live.
- **BAND does not show it (decided).** BAND reads `/api/radio/bandmap` and `/api/radio/state` over REST and
  subscribes to no hub stream, so a hub drop does not affect it; it already has its own API-failure handling
  (messages, kept map, idle cadence).
- **Plumbing:** `AudioVisualizationHubService` raises a new `ConnectionStateChanged` on first connect, a
  retry-loop connect, reconnecting, reconnected, closed and stop. Previously the panel learnt of a change only
  if something else re-rendered it. `IsConnectedOverride` is an `internal` test seam (bUnit cannot reach a
  live hub); production never sets it.

## Tests (`VisualizerPanelConnectionTests`, 7; plus one in `VisualizerPanelBandTests`)

Shown when disconnected (role, live region, text, icon); precedence over "Waiting for audio data"; hidden
when connected (and "Waiting" shows instead); no dot in either state; a drop shows it and clears the canvas, a
reconnect removes it; a disconnected notification with no change does not clear; dispose unsubscribes.
`Band_HubDisconnected_ShowsNoDisconnectedState`. Mutation results are in the PR body.

## Owner check

Stop `radio-api` (or otherwise break the hub) with Spectrum showing: the visualizer area shows the
disconnected icon and "Visualizer disconnected / Reconnecting…". Start it again: the state disappears and the
spectrum resumes. There is no green or red dot on the picker at any time.
