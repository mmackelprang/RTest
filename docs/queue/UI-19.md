# `UI-19` — the API's "skip FFT when nobody is watching" gate is effectively always off

[← Builder Queue index](../BUILDER_QUEUE.md)

🟢 **P3.** Filed 2026-09-30 on the owner's ruling to queue the `UI-10` follow-ups ([`RETURN-CHECKLIST.md`](../uat/RETURN-CHECKLIST.md) §6: *"Ruled 2026-09-30: queue them"*). CPU saving, not correctness.

## Provenance

Found by the `UI-10` pre-merge reviewer on 2026-09-28 and recorded, not fixed, in two places:

- [`queue/UI-10.md`](UI-10.md) § *Root cause 2026-09-28*, "Found by the reviewer, not fixed here": *"Because radio-web's singleton connection is never stopped, `AudioVisualizationHub.ConnectedClients` stays ≥ 1, so `VisualizationBroadcastService`'s "skip FFT work when nobody is watching" gate is effectively always off on the box."*
- [`uat/OWNER-REVIEW.md`](../uat/OWNER-REVIEW.md) Phase 2d, "Filed, not fixed, found while fixing UI-10".

No `HANDOFF-GA-PUNCH-LIST.md` counterpart.

## The finding

`VisualizationBroadcastService` skips its FFT work when `AudioVisualizationHub.ConnectedClients` is zero. `radio-web` holds one singleton `HubConnection` to `/hubs/visualization` for the life of the process, so the count never reaches zero and the skip never happens: the API does the FFT work continuously on a box where CPU is scarce.

## Scope questions for the plan

1. Gate on what someone is watching (membership of the Spectrum/Levels/Waveform groups) instead of on connections? Then `UI-18`'s leak is what would keep it on, so the two rows should land together or `UI-18` first.
2. Or stop/idle `radio-web`'s connection when no visualizer is shown? ⚠ `UI-10` found this connection racing its keepalive when it carries no traffic (fixed by `KeepAliveInterval = 15 s`, [#705](https://github.com/mmackelprang/RTest/pull/705)); a design that leaves it connected but silent must not bring that back.
3. What does it cost? Measure `Radio.API` CPU on the box with nothing watching, before and after, so the saving is a number rather than an expectation.

## Verification

A unit test that the broadcast service does no FFT work when no client is subscribed to a visualization group, and does when one is. On the box: the before/after CPU measurement above.
