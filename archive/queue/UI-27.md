# `UI-27` — the CLIP pill shifts the radio panel by 3 px every time it appears

[← Builder Queue index](../BUILDER_QUEUE.md)

✅ **SHIPPED AND OWNER-VERIFIED 2026-10-01 — [#761](https://github.com/mmackelprang/RTest/pull/761), squash `4d483ff`; archived.** See [§ Shipped](#shipped-2026-10-01) at the foot of this file.

🟡 **P2 (owner report, visible on every overload).** Filed 2026-10-01 by the coordinator.

> *"On the radio panel when the `CLIP` tag appears above the signal strength bar, it causes the whole
> screen to "shift" by a couple of pixels. This is distracting and should be fixed."*

## Cause — measured

The pill sat in the RSSI header (`.rcp-meter-header` in `RadioControlPanel.razor`) behind
`@if (_radioState.Clip)`, inside the dBu readout (an `inline-flex`). It is **19.5 px** tall
(9 px text, 2 px padding, 1 px border) against the header's **16.5 px**. So each time it appeared the
header grew 3 px. The tuner column is a top-aligned flex column, so everything below the meter moved down
3 px with it: the bar, the scale, the tune/scan controls and the AGC row. CLIP flickers with the signal,
so the panel jittered.

Measured in Chromium at 1920×720, live (local `Radio.Web` on `origin/main` `7d2124e`, the box's real
state through a GET-only proxy with `clip` forced):

| | CLIP off | CLIP on |
|---|---|---|
| `.rcp-meter-header` height | 16.5 | **19.5** |
| `.rcp-meter-bar` top | 387.5 | **390.5** |
| `.rcp-controls` top | 425.5 | **428.5** |

Inside the header the "RSSI" label also dropped 1 px and the dBu readout 1.5 px, because the readout's
baseline became the pill's.

**Not a regression from `UI-20`.** The same harness on the pre-`UI-20` tree (`f30ed06`) shows the
identical +3 px. The conditional pill dates from #367 (2026-05-17). `UI-20`'s move of the scan chip into
this header was checked as well: the chip is 11 px tall (`line-height: 1`, no vertical padding) and changes
no rect.

The other candidates were ruled out. No scrollbar appears: `.rcp-root` and `.rcp-tuner` are
`overflow: hidden`, and the measurement shows a 3 px move, not a 3 px scrollbar. No line-height change
outside the header either.

## Fix

- **Always rendered.** `<span class="rcp-clip-pill @(Clip ? "is-on" : "")">CLIP</span>`, so the DOM
  never gains or loses an element.
- **Out of flow.** In `design-system.css` §S, `.rcp-clip-pill` is `position: absolute` against
  `.rcp-meter-readout` (now `position: relative`): `right: calc(100% + 6px)`, vertically centred. It is
  `visibility: hidden` until `.is-on`, which also keeps it out of the accessibility tree when off. It sits
  where it did before (6 px left of the dBu readout), and its 19.5 px box overhangs the 16.5 px header by
  1.5 px each side, into the header's 4 px bottom margin.
- **The header keeps today's no-CLIP geometry** (16.5 px), which is the figure `UI-20`'s tuner-column
  budget was measured against.

**After, the same live measurement:** zero rect differences across CLIP off, CLIP on, scanning, and both,
for the header, meter bar, scale, controls, frequency well, band row and preset bar.

## Tests

- `RadioControlPanelTests.MeterHeader_HasTheSameElements_WithAndWithoutClip` (4 cases: CLIP × scanning).
  The header holds the same elements in the same order either way, and only `is-on` differs.
- `SignalMeter_ShowsClipPill_WhenClipTrue` / `SignalMeter_HidesClipPill_WhenClipFalse`, updated for
  `.is-on`.
- `Css_ClipPill_TakesNoRoomAndIsHiddenUntilOn` pins `position: absolute`, `visibility: hidden` (never
  `display: none`), `.is-on → visible`, and the readout's `position: relative`. bUnit computes no styles,
  so this is the geometry's guard.

**Mutation checks: 7 of 7 killed.** The mutants:

1. insert the pill on demand again;
2. `display: none`;
3. `position: static`;
4. drop the `.is-on` rule;
5. always `is-on`;
6. drop the readout's `position: relative`;
7. drop `right: calc(100% + 6px)`, which would put the pill on top of the readout. This one was added
   after the reviewer's L7.

## Review

The pre-merge reviewer confirmed two claims:

- `visibility: hidden` takes the pill out of the accessibility tree and out of hit-testing;
- the header's `opacity: 0.7` still dims it through the readout, as before.

⚠ **One known limit, measured (reviewer L4).** Out of flow, the pill no longer pushes the scan chip
aside. It overlaps the centred `SIGNAL −12 dBu` / `SCANNING DOWN` chip only when the RSSI header is
narrower than about 320 px:

| Header width | Gap from chip to pill |
|---|---|
| 586 px (the kiosk at 1920×720) | 137 px |
| 420 px | 54 px |
| 340 px | 14 px |
| 300 px | −6 px (overlap) |

The panel's tuner column is fixed on the kiosk, so this never happens there.

## Owner check

**CLIP flicker no longer moves the screen.** On a strong station (or with the gain up) while CLIP comes
and goes, nothing below the RSSI header moves. The pill still appears to the left of the dBu figure.
