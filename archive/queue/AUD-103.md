# `AUD-103` — Band map for AM and SW: sweep plans, the HF mode in both sweep paths, and an UnavailableReason that reads the device

[← Builder Queue index](../../docs/BUILDER_QUEUE.md)

🟢 **P2, fourth all-band row.** Filed 2026-10-11 by the Planner. Read from code on `main` `2a2893d2`.

## Goal

The BAND view, Discover and map-driven Scan (`AUD-91`, `AUD-100`) should work on AM and SW the way they already
work on FM, WB, AIR and VHF.

## Measured facts

- **No AM or SW plan.** `BandSweepPlans.For` (`src/RTLSDRCore/Sweep/BandSweepPlans.cs:112-127`) handles FM, WB,
  AIR and VHF only. The class remarks say so (`:24`).
- **`UnavailableReason` uses static constants, not the device.** `:134-165` compare the preset range with
  `RtlSdrDevice.TunerMinFrequencyHz/TunerMaxFrequencyHz`. Its callers: `BandMapService.cs:271,340,1076`
  (`GetScanStations`, the request path, `MappableBands`) and `BandMapController.cs:83,136`. The Web shows it at
  `VisualizerPanel.razor:159-161`.
- ⚠ **Correction to the 2026-10-11 survey ("`ChannelPowerMeter` window is FM-sized"): only the parameter
  defaults are.** `ChannelPowerMeter`'s defaults are 80 kHz / 8 kHz (`ChannelPowerMeter.cs:62-63`), but
  `BandSweeper` always passes the plan's own window (`BandSweeper.cs:155,162`). `AUD-91` already gives
  narrowband plans **±4 kHz with 1 kHz DC exclusion** (`BandSweepPlans.cs:36-39`), and `CreateNarrowband`
  (`:180-206`) puts every channel at least half a spacing from the tuned centre. **A 10 kHz AM grid fits that
  as it is**: `NarrowbandGroupSize(10_000)` = 20 channels per tune, so 119 channels (530–1710 kHz) take 6 tunes.
  At 5 kHz SW it is 38 per tune. No new window type is needed unless the box shows otherwise.
- **Two sweep paths**, and both must be in HF mode for AM/SW: the idle path `DeviceSweepTuner`
  (`src/RTLSDRCore/Sweep/DeviceSweepTuner.cs:44-63`, opened by `BandMapService.RunIdle` `:748`) and the live path
  `RadioReceiver.RunLiveSweep` / `LiveSweepTuner` (`RadioReceiver.cs:1166-1240`, `:1326-1342`). `AUD-99` adds
  the switch itself. This row makes sure the sweeps ask for it and adds tests at the sweep level.
- **Sweep gain.** Both paths force manual tuner gain (`DeviceSweepTuner.cs:58-59`, `RadioReceiver.cs:1204-1205`;
  `BandMapOptions.SweepGainDb`). In direct-sampling mode the tuner is in standby and tuner gain means nothing.
  The sweep must not log an error per tune for it (see `AUD-99`), and AM levels will sit on a different absolute
  scale from FM's. Check the `UI-22` signal-colour thresholds (12/20 dB above floor) against real AM maps before
  trusting the colours.

## Scope

1. **AM plan:** 530–1700 kHz (or to the AM top edge `AUD-102` settles) at 10 kHz, through `CreateNarrowband`.
2. **SW plan.** The whole of 1.7–30 MHz at 5 kHz is about 5,700 channels. That is too many to sweep and to show.
   Recommended: follow the VHF precedent (`CreateVhf`, `:250-265`, a window that follows the radio). The SW plan
   is the **broadcast segment** containing (or nearest to) the radio's frequency, from a fixed table: 120/90/75/
   60/49/41/31/25/22/19/16/15/13/11 m, with ITU edges recorded in code. The plan states the table's source.
   ⚠ How the BAND view's axis presents a segment, and how Discover picks one when the radio is not on SW, are
   presentation questions. If the plan cannot answer them from `UI-31`'s existing strip and axis, ask the
   Designer briefly rather than inventing it.
3. **`UnavailableReason` reads the device.** Use the same capability `AUD-102` puts on `RadioBandModel` (one shared
   function, not a copy). The text for a device without HF should still read like today's sentence.
   `MappableBands` and the controller follow it. Keep the custom-band case.
4. **Sweeps in HF mode.** Both paths set HF mode per the plan's band before the first tune, and the idle sweep
   restores nothing (it closes the device). The live path only sweeps a band in the radio's current mode, or
   refuses with a reason (`AUD-99` § Scope 2 decides the mechanism).
5. **Map-driven Scan (`AUD-100`) on AM/SW.** `GetScanStations` (`BandMapService.cs:262-…`) works once the plan
   exists. Check the 10 kHz/5 kHz spacing assumptions in `BandMapStations.Peaks` and the seek-stop merge.

**3. Design ruling for SW presentation (the coordinator's, taken as given).** The SW plan follows the radio exactly as
VHF's window does. While the radio is on SW, the segment is the radio's. **Off SW, Discover on SW sweeps the segment
nearest the SW band memory**, read through `IRadioBandMemory.GetAsync(RadioBand.SW)` (a new optional
`shortwaveMemoryHz` delegate on `BandMapService`; DI calls the async read synchronously, which runs off any
synchronization context and catches its own store failures); with nothing remembered the memory's own default is SW's
bottom edge rounded to 1715 kHz (AUD-102), whose nearest segment is **120 m**, the same segment `For(SW, null)` picks.
The BAND view shows a segment the way it shows VHF's window: the same strip and axis, with the segment's name in the
strip's band-name text: **`SW 31 m`** in `.band-strip-name` and **`9400–9900 kHz`** in `.band-strip-range` (together the
ruling's "SW 31 m · 9400–9900 kHz"). No other UI was added; the VHF-only `Window` chip is not shown for SW (the name says
which part of the band it is). The name comes from the API: `BandMapResponseDto.Segment` (`"31 m"`, null on every other
band), computed by `BandMapController.WithAxis` from the axis's edges (`ShortwaveSegments.WithEdges`), so a stored map
of another segment is named for what it shows. A stored map that recorded its range overrides the plan's axis for SW as
for VHF (`windowStored = storedRange && FollowsRadio(band)`), and the timer treats a fresh SW map as due once the radio
has left its segment (`CoversPlan`, unchanged code, now reached by SW).

**4. `UnavailableReason` reads the device.** `BandMapService.UnavailableReason(BandType)` (`BandMapService.cs:1117`)
calls `BandSweepPlans.UnavailableReason(band, deviceMinHz, deviceMaxHz)` (`BandSweepPlans.cs:157`), which is
`BandReception.UnavailableReason(..., cannot: "scanned")`, AUD-102's one function. The device is the band list's own
choice, now one shared function: **`Radio.Infrastructure.Services.SdrReceivingDevice.Find(IRadioFactory)`** (the radio's
in-use device, else the first enumerated, else null; a throwing factory is null), used by `RadioBandService` (its private
copy is gone) and, through the new `receivingDevice` delegate, by `BandMapService`. **No device known** (no dongle, tests)
means **no device limit**, as on the band list: every preset band can be swept (an idle sweep then reports
`no-sdr-device`), and only a custom band gets its sentence. The static-range overload `BandSweepPlans.UnavailableReason(band)`
is removed. Callers moved: `GetScanStations`, `RecordSeekStation`, `PlanFor` (request, timer, `GetPlan`) and
`BandMapController.Scan`/`WithAxis`. `MappableBands()` is gone: the constructor now loads every band's stored map and seek
stations, because asking the device there would resolve `RadioFactory` while it may itself be resolving this service (it
takes `IScanStationMap`). A stored map of a band the device cannot sweep is served without channels (`Get` passes no map).
The sentence on a dongle without HF is unchanged: *"The AM Broadcast band (530–1,710 kHz) is below this tuner's 24 MHz
lower limit and cannot be scanned."* `RTLSDRCore` 1.3.0 → 1.4.0 (removed overload, new public `ShortwaveSegments`).

**5. HF mode on both paths.** No production change was needed: `AUD-99` already wired both.
- Idle: `RunIdle` opens `DeviceSweepTuner(device, gain, HfBands.Requires(run.Plan))` (`BandMapService.cs:798`), whose
  `Open` switches HF on before the sample rate and any tune. Now reached by the real AM/SW plans.
- Live: `RadioReceiver.SweepPlan` → `RunLiveSweep` refuses a plan whose band needs the other mode (`ModeConflict`), and
  `BandMapService` asks first through `ILiveBandSweeper.LiveSweepRefusal` (`:735`) and answers `radio-other-hf-mode` (409).
  So AM/SW can be swept live only while the radio plays AM or SW, and FM/WB/AIR/VHF only while it plays one of those.
- **Gain**: both paths set the sweep's manual gain once (idle: in `Open`; live: before the first hop, restored after
  the last), never per tune; in HF mode `RtlSdrDevice`/`MockSdrDevice` skip it at Debug (`AUD-99`). The new tests pin
  "once, not per tune" on both paths.

**6. Map-driven Scan (`AUD-100`) on AM/SW.** `GetScanStations` needed no spacing change: the gap is half the map's
spacing (5 kHz on AM, 2.5 kHz on SW, so a 2.5 kHz-step SW frequency is never mistaken for the station beside it), a
seek-observed station merges only when at least one spacing from every peak, and the range check uses the stored range
(SW's segment). Off the stored SW segment Scan seeks live (`outside-map`); a flat map seeks live (`no-other-station`).
`RecordSeekStation` now records AM/SW stops; their `SeekStrength` is the in-channel scale (AUD-101), compared only
within one band, and the `BandMapSeekStation`/DTO docs now say so.

**7. The 960 kHz spur: built.** ⚠ As first built, only the map-driven path filtered it: the live seek still
stopped on 960 kHz and recorded a ring there. Fixed by review fix M1 (below). `BandMapStations.KnownSpurs` (`src/Radio.Core/Models/BandMap.cs:61`) is a data table of
**measured** spurs, one entry: 960 kHz ± 2 kHz, *"RTL2832U 28.8 MHz reference ÷ 30; measured on the NESDR SMArt v5"*.
`Peaks` drops spur channels **before** the peak rule (`:105`), so a spur is never a peak, is not in the median, and does not
hide a real carrier beside it (970 kHz, the 968 kHz carrier, is still a peak although 960 is higher). `GetScanStations` also
drops a seek-observed station on a spur (`BandMapService.cs:352`), so neither a tap nor Scan stops there. The bar is still
measured, stored and drawn, in the noise colour (`FmBandMath.SignalTiers`, which also leaves spurs out of its median).
**Why a measured list and not `28.8 MHz ÷ n`:** the formula puts a sub-harmonic near every AM channel (n = 17 to 54);
28.8 MHz ÷ 28 = 1028.6 kHz is 1.4 kHz from **1030 kHz, the real nighttime skywave signal the ruling says must not be
excluded**, and 28.8 MHz ÷ 3 = 9.6 MHz is a 31 m broadcast channel that read at the floor. A formula within "a few kHz"
would have hidden both.

**8. `UI-22` colours against the AM numbers (assessed, not retuned).** The tiers are relative to the map's median
(Weak ≥ +6, Fair ≥ +12, Strong ≥ +20 dB), and so are the bar heights (10th percentile to max, min span 10 dB): nothing in
the band map is tied to FM's absolute levels, so AM's different absolute scale changes nothing. With the box's in-channel
readings (floor about −50): **960 kHz +16 dB → Fair by level, now drawn as Noise (spur)**; 1030 kHz +7.8 → Weak;
970 kHz (968 carrier) +6.2 → Weak; 1400 +4.6 and 680 +3.8 → Noise (the elevated hump does not colour); SW 5.000 MHz
+6.7 → Weak; 9.6 MHz → Noise. So on the passive antenna **every real AM/SW signal measured so far draws blue (weak),
none cyan or green**, and the spur would have been the only cyan bar. The sweep's mean-bin-power level over ±4 kHz and
the radio's in-channel meter over the channel filter are both carrier-plus-noise over a similar bandwidth, so their
dB-above-floor should agree to about a dB; the box map is the check. Not retuned (out of scope); worth filing only if the
owner wants colour to separate AM stations on this antenna.

**9. Measurement window: kept, one invariant relaxed for AM/SW.** No new window type. AUD-91's narrowband invariant "no
channel's window reaches the DC exclusion" (`Narrowband_EveryChannelWindowFitsTheCapture_AndNoneTouchesDc`, WB/AIR/VHF)
does **not** hold for AM/SW and is not asserted for them: on AM the nearest channels are 5 kHz from the tune centre and their
±4 kHz windows reach exactly the ±1 kHz exclusion's edge; on SW they are 2.5 kHz away and overlap it by 1.5 kHz. The
excluded bins are simply not measured; the carrier itself (≥ 2.5 kHz out) always is. The AM/SW test asserts that instead.
⚠ **Superseded by review fix M2 (below):** AM/SW tunes now keep every window at least 12 kHz from the centre, so
the pairs listed here no longer exist. *Was:* **What to watch on the box:** if the direct-sampling DC spike leaks past 1 kHz, the two channels either side of each tune
centre rise together: on AM, pairs at **620/630, 820/830, 1020/1030, 1220/1230, 1420/1430, 1620/1630 kHz**; on SW 31 m,
around 9492.5, 9682.5 and 9842.5 kHz. ⚠ 1030 kHz is one of them, so read a raised 1030 together with 1020.
